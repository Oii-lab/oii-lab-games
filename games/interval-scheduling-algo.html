Step 1 · 問題定義
有 n 個活動，每個活動有開始時間 s[i] 和結束時間 f[i]。
同一時間只能參加一個活動（不能重疊），求最多能參加幾個活動。

兩個活動 i, j 不衝突的條件：f[i] ≤ s[j] 或 f[j] ≤ s[i]
Step 2 · 三種直覺策略的反例
先來看三個「看起來合理」但都是錯的策略：
❌ 策略一：選最短的活動
直覺：短的活動佔用時間少，應該能選更多。
反例：活動 A(1~3)、B(2~4)、C(1~10)（最短）

❌ 策略二：選最早開始的活動
直覺：早開始的先處理，剩下更多時間。
反例：活動 A(1~9)、B(2~4)、C(5~7)

選最早 A → 只能選 1 個。但選 B+C → 選 2 個。最早開始策略失敗！
❌ 策略三：選衝突最少的活動
直覺：選擇對其他活動影響最小的。
反例：A(1~3)、B(2~4)、C(3~5)、D(1~5)（只和A,B,C衝突，其他活動不存在）
在某些特殊配置下，衝突最少的活動並不是最優選法。
Step 3 · 正確的貪心策略
正確答案：每次選結束時間最早的不衝突活動。
Python 
def interval_scheduling(activities):
    # 按結束時間排序
    sorted_acts = sorted(activities, key=lambda x: x.end)

    selected = []
    last_end = 0  # 上一個選中活動的結束時間

    for act in sorted_acts:
        if act.start >= last_end:  # 不衝突
            selected.append(act)
            last_end = act.end

    return selected

# 時間複雜度：O(n log n)（排序）+ O(n)（掃描）= O(n log n)
# 空間複雜度：O(n)
💡 直覺 選結束最早的活動，讓剩下的時間最多。
這樣後面才有最大的機會選更多活動。
Step 4 · 為什麼最早結束是最優：交換論證
用交換論證（Exchange Argument）來嚴格證明。

假設最優解 OPT 選了活動序列 a₁, a₂, …, aₖ（按結束時間排序）
貪心解 GREEDY 選了 g₁, g₂, …, gₘ（按結束時間排序）

引理：對所有 i，g[i].end ≤ a[i].end
（貪心的第 i 個選擇，結束時間不晚於最優解的第 i 個選擇）
歸納法證明引理：

基礎：i=1 時，g₁ 是結束最早的活動，所以 g₁.end ≤ a₁.end ✓

歸納：假設 g[i].end ≤ a[i].end，考慮第 i+1 步：
・a[i+1] 的開始時間 ≥ a[i].end ≥ g[i].end
・所以 a[i+1] 對貪心也是合法的選擇
・但貪心選的是結束最早的合法活動 g[i+1]
・所以 g[i+1].end ≤ a[i+1].end ✓

結論：如果最優解選了 k 個，貪心也至少能選 k 個，
所以貪心解 = 最優解。
🔑 交換論證的精髓 不需要枚舉所有可能，只需要證明「把最優解換成貪心解，不會變更差」。
這是證明貪心算法正確性的標準方法。
Step 5 · 和背包問題的對比
區間排程 背包問題
目標 數量最多 價值最大
限制 時間不重疊 重量不超限
貪心 ✅ 最優 ❌ 不一定
最優演算法 Greedy O(n log n) DP O(n·W)
關鍵性質 最優子結構 + 貪心選擇 最優子結構（無貪心選擇）
💡 貪心 vs DP 兩個問題都有「最優子結構」，但區間排程還有「貪心選擇性質」：
局部最優（每步選結束最早）能導向全局最優。
背包問題沒有這個性質，所以必須用 DP 枚舉所有可能。
