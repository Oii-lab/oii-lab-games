Step 1 · 和前面遊戲最大的不同
Bachet、Nim、Wythoff 都有 O(1) 或 O(N) 的公式，可以瞬間判斷輸贏。

Chomp 完全不同：目前數學界沒有任何已知公式。
唯一已知的是「先手必勝」這個存在性結果，但沒人知道先手應該怎麼走。

電腦只能用 Minimax 搜尋：把所有可能的走法都試一遍，找到必勝的那步。
🤯 Chomp 的特殊地位 這是一個你可以輕鬆玩、規則很簡單，但連最頂尖的數學家都不知道完整策略的遊戲。
困難模式的電腦在大棋盤上也可能走錯——因為這個問題連電腦都要花很長時間搜尋。
Step 2 · Zermelo 定理：先手必勝的存在性證明
雖然不知道策略，但我們能證明先手必勝一定存在。
這用的是 策略竊取論證（Strategy Stealing Argument）：
假設後手有必勝策略 S

先手第一步吃掉右上角的一塊（任意走法）
↓
現在先手處於一個「後手的位置」，可以開始執行策略 S
↓
但等等——先手已經多吃了一塊，比「後手剛開始」的狀態多做了一步
多吃一塊只會讓局面「更少」，在 Chomp 中這只有可能更好（永遠不會讓你更不利）
↓
所以先手也能執行 S，而且效果至少一樣好
↓
矛盾！後手不可能有必勝策略 → 先手必勝 ✓
💡 存在性 ≠ 可建構性 這個證明只告訴我們「先手必勝策略存在」，但完全沒有說策略是什麼。
這在數學上很常見：證明某東西存在，但不知道它長什麼樣子。
Step 3 · Minimax 搜尋
沒有公式，只能搜尋。Minimax 的核心思想很直接：
Python 
def is_losing(board) -> bool:
    """當前玩家是否在必輸位置"""

    # 只剩毒格 → 被迫吃 → 必輸
    non_poison = [(r,c) for r,c in board if (r,c) != (0,0)]
    if not non_poison:
        return True

    # 嘗試每一種走法
    for (r, c) in non_poison:
        # 吃掉 (r,c) 及右上方所有格
        after = frozenset(
            (rr, cc) for rr, cc in board
            if not (rr >= r and cc >= c)
        )
        # 如果這步能讓對手進入必輸位置，我就贏了
        if is_losing(after):
            return False  # 我能贏 → 我不是必輸

    # 所有走法都讓對手贏 → 我必輸
    return True
注意這裡沒有「最大化/最小化」的顯式邏輯，因為兩個玩家都在「找能讓對手必輸的走法」，
本質上是同一件事——這是 Minimax 在零和博弈中的簡化形式。
Step 4 · Memoization 為什麼關鍵
不加 Memoization，時間複雜度是 O(走法數!)，棋盤稍大就根本跑不完。

關鍵觀察：不同的走法順序可能到達相同的棋盤狀態。
例如 3×3 棋盤：
走法 A → 走法 B → 棋盤狀態 X
走法 B → 走法 A → 棋盤狀態 X（相同！）

沒有 Memo：兩條路都重新計算狀態 X
有 Memo：第二次遇到 X 直接查表，O(1) 回答
Python 
from functools import lru_cache

@lru_cache(maxsize=None)
def is_losing(board: frozenset) -> bool:
    # 完全相同，但加了 @lru_cache
    # frozenset 是 hashable，可以當 cache key
    non_poison = {(r,c) for r,c in board if (r,c) != (0,0)}
    if not non_poison: return True
    for (r, c) in non_poison:
        after = frozenset((rr,cc) for rr,cc in board if not(rr>=r and cc>=c))
        if is_losing(after): return False
    return True

# 複雜度：O(唯一棋盤狀態數 × 平均合法走法數)
# 3×3：幾十個狀態，瞬間完成
# 5×4：幾千個狀態，約 0.1 秒
# 7×5：幾十萬狀態，可能需要數秒
🔬 JS 版的差異 遊戲中的 JS 實作用字串當 key（board 轉成 "0101|1111|…"），
原理完全相同，只是 Python 的 frozenset 換成字串 hash。
大棋盤（7×5 以上）搜尋時間會明顯增加，這是 Chomp 的本質限制。
Step 5 · 為什麼是開放問題
Chomp 被數學界列為未解問題，原因在於棋盤狀態數的爆炸性增長：
棋盤 格子數 有效狀態數（約） 狀態
2×N2N O(N²) ✅ 已有公式
3×N3N O(N³) ✅ 已有公式
4×416 數千 ✅ 電腦可解
5×525 數萬 ✅ 電腦可解
N×N（大）N² 指數級 ❌ 無公式，電腦也解不了
一般 M×NMN 指數級 ❌ 開放問題
關鍵差異在於：Nim 和 Bachet 有代數結構（XOR、模運算），
讓問題可以被「壓縮」成公式。
Chomp 的棋盤形狀是「Young diagram」（楊圖），目前沒有發現類似的代數結構。
📚 延伸閱讀 Chomp 由 David Gale 在 1974 年提出，至今 50 年仍未解決。
已知有公式的特例：1×N（平凡）、2×N、3×N、正方形 N×N（先手走 (2,2) 必贏，但為什麼未知）。
