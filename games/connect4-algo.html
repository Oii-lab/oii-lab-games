Step 1 · 和 Chomp 的差異：為什麼需要深度限制
Chomp 和 Connect Four 都用 Minimax，但有一個關鍵不同：

Chomp：狀態數有限，可以搜尋到底（終局），得到精確答案。
Connect Four：7×6 棋盤有超過 4 兆種可能局面，不可能搜尋到底。

解法是加入深度限制（depth limit）：搜尋到指定深度後，用評估函數估計局面好壞，而非繼續搜尋。
搜尋深度 節點數（約） 時間（JS） 強度
37³ ≈ 343 <1ms簡單
57⁵ ≈ 16,807 <10ms普通
77⁷ ≈ 823,543 ~100ms困難
完整搜尋>4兆 幾小時完美
💡 有 Alpha-Beta 後 Alpha-Beta 剪枝可以把節點數降到約 7^(d/2)，深度 7 只需約 2,800 個節點，速度快很多。
Step 2 · Minimax 博弈樹
Minimax 的核心：把遊戲展開成樹，兩個玩家輪流選擇：
・Max 層（我的回合）：選分數最高的走法
・Min 層（對手的回合）：選分數最低的走法（對對手最有利）
Python 
def minimax(board, depth, maximizing):
    # 終止條件
    if is_win(board, CPU):   return +100000
    if is_win(board, HUMAN): return -100000
    if is_full(board):        return 0
    if depth == 0:           return evaluate(board)  # 深度到了，估分

    if maximizing:  # 我的回合，找最大分
        best = -float('inf')
        for col in valid_cols(board):
            drop(board, col, CPU)
            best = max(best, minimax(board, depth-1, False))
            undo(board, col)
        return best
    else:           # 對手回合，找最小分
        best = +float('inf')
        for col in valid_cols(board):
            drop(board, col, HUMAN)
            best = min(best, minimax(board, depth-1, True))
            undo(board, col)
        return best
Step 3 · Alpha-Beta Pruning
Minimax 要搜尋所有分支，Alpha-Beta 加入兩個界限來跳過「不可能被選到」的分支：

α（alpha）：Max 層目前找到的最佳分數（我能保證的下限）
β（beta）：Min 層目前找到的最佳分數（對手允許的上限）

當 α ≥ β，代表這個分支的結果對任一方都不會被選到，直接剪掉。
Python 
def alpha_beta(board, depth, alpha, beta, maximizing):
    if is_win(board, CPU):   return +100000 + depth  # 越快贏分越高
    if is_win(board, HUMAN): return -100000 - depth
    if is_full(board):        return 0
    if depth == 0:           return evaluate(board)

    if maximizing:
        value = -float('inf')
        for col in valid_cols(board):
            drop(board, col, CPU)
            value = max(value, alpha_beta(board, depth-1, alpha, beta, False))
            undo(board, col)
            alpha = max(alpha, value)
            if alpha >= beta: break  # β 剪枝：對手不會讓我走到這
        return value
    else:
        value = +float('inf')
        for col in valid_cols(board):
            drop(board, col, HUMAN)
            value = min(value, alpha_beta(board, depth-1, alpha, beta, True))
            undo(board, col)
            beta = min(beta, value)
            if alpha >= beta: break  # α 剪枝：我已有更好選擇
        return value
📐 剪枝效果 沒有排序：最差 O(b^d)，最好 O(b^(d/2))
有好的走法排序：接近最好情況 O(b^(d/2))
也就是說，好的排序讓你用同樣時間搜尋雙倍深度。
Step 4 · 啟發式評估函數
深度到了不能再搜尋時，用評估函數打分。這裡用的是「四格視窗掃描」：
把棋盤上每一個長度 4 的橫、縱、斜視窗都計算分數，加總起來。
Python 
def score_window(window, cpu, human):
    cpu_count   = window.count(cpu)
    human_count = window.count(human)
    empty       = window.count(0)

    if cpu_count == 4:             return +100   # 連四（終局已處理，這裡備用）
    if cpu_count == 3 and empty == 1: return +5   # 三子+空格，威脅連四
    if cpu_count == 2 and empty == 2: return +2   # 兩子+兩空格，潛力
    if human_count == 3 and empty == 1: return -4  # 對手三子，緊急防守
    return 0

def evaluate(board, cpu):
    score = 0
    center = len(board[0]) // 2

    # 中間列加權（中心控制更有利）
    for row in board:
        if row[center] == cpu: score += 3

    # 掃描所有四格視窗
    for window in all_windows(board):
        score += score_window(window, cpu, human)

    return score
⚠️ 評估函數的限制 評估函數是「猜測」，不是精確值。
設計不好的評估函數可能讓電腦走出看似有利但實際上的敗著。
改進方向：加入更多模式（開放四、雙威脅）、或用機器學習訓練評估函數。
Step 5 · 走法排序：讓剪枝更有效
Alpha-Beta 的效果取決於走法的順序：越好的走法越先搜尋，剪掉的分支越多。

Connect Four 的最簡單排序技巧：從中間列開始搜尋。
中間列通常是最強的走法（同時威脅多個方向），先搜尋它能更快建立好的 α/β 界限。
Python 
def valid_cols_ordered(board):
    cols = valid_cols(board)
    center = len(board[0]) // 2
    # 按距離中心的距離排序（中心優先）
    return sorted(cols, key=lambda c: abs(c - center))

# 7列棋盤中心=3，排序結果：[3, 2, 4, 1, 5, 0, 6]
# 進階技巧：可以先快速搜尋淺層，用結果排序再深搜（Iterative Deepening）
Step 6 · Connect Four 完全解（1988年）
1988 年，James Dow Allen 和 Victor Allis 各自獨立證明了 Connect Four 的完全解：
🏆 完全解結果 標準 7×6 棋盤：先手必勝，最優走法是投入第 4 列（中間列）
他們用的方法是「威脅序列分析」（Threat Combination），不是暴力搜尋：
分析棋盤上所有潛在的四子連線威脅，找出能同時製造無法同時防守的雙重威脅的走法。

這和我們遊戲中的 Alpha-Beta 不同——完全解是精確的，Alpha-Beta 在深度不足時只是近似。

6×5 後手必勝 —
8×7 先手必勝 第 4 或 5 列
