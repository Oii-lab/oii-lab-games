Step 1 · 為什麼必須排序
Binary Search 的核心假設：看到 arr[mid] 之後，能排除一半的搜尋範圍。

這只在排序陣列中成立：
已排序
arr[mid] < target
→ target 一定在右半
→ 可以安全砍掉左半 ✅
未排序
arr[mid] < target
→ target 可能在任何地方
→ 不能砍掉任何一半 ❌
💡 關鍵洞察 排序讓每次比較都有「方向性」。沒有方向性，就只能線性掃描。
這也是為什麼排序 O(n log n) + 二元搜尋 O(log n) 比線性搜尋 O(n) 更值得：一次排序，多次搜尋。
Step 2 · 標準模板：左閉右閉 [lo, hi]
Binary Search 有幾種寫法，最容易理解的是左閉右閉區間：[lo, hi] 代表搜尋範圍包含兩端。
Python 
def binary_search(arr: list, target: int) -> int:
    """回傳 target 的 index，找不到回傳 -1"""
    lo, hi = 0, len(arr) - 1   # [lo, hi] 都包含

    while lo <= hi:              # 等號：lo==hi 時還有一個元素要檢查
        mid = (lo + hi) // 2

        if arr[mid] == target:
            return mid           # 找到！
        elif arr[mid] < target:
            lo = mid + 1          # 往右找（mid 已確認不是，所以 +1）
        else:
            hi = mid - 1          # 往左找（mid 已確認不是，所以 -1）

    return -1                   # lo > hi，搜尋範圍空了，找不到
每一行的選擇都有原因：
hi = len(arr) - 1 → 右端是最後一個合法 index，區間 [0, n-1]
while lo <= hi → lo == hi 還有一個元素，不能漏掉
lo = mid + 1 → arr[mid] 已確認不是 target，不用再看
hi = mid - 1 → 同理，arr[mid] 已排除
Step 3 · 邊界條件：最容易出 bug 的地方
Binary Search 概念簡單，但寫錯的人非常多。常見錯誤：
❌ 錯誤 1 · while lo < hi
用 < 而非 <=：當 lo == hi 時提早結束，可能漏掉最後一個元素。
例：陣列只剩 [7]，lo=hi=3，直接跳出，回傳 -1，但 7 其實就在那裡。
❌ 錯誤 2 · lo = mid 或 hi = mid
不寫 mid ± 1：arr[mid] 已確認不是 target 還把它留在範圍內，可能無限迴圈。
例：lo=3, hi=4, mid=3。arr[3] 不是 target，若 lo=mid=3，下次還是 mid=3，永遠跑不完。
❌ 錯誤 3 · mid = (lo + hi) / 2 整數溢位（C/Java）
Python 整數不溢位，但 C/Java 中 lo+hi 可能超過 int 上限。
安全寫法：mid = lo + (hi - lo) // 2
✅ 記憶口訣 「hi 初始化到最後一個合法 index（n-1）→ 用 <= → 更新時 ±1」
三件事配套，缺一就出 bug。
Step 4 · O(log n) 怎麼來的
每次迴圈，搜尋範圍從 n 縮小到 n/2：
步數 剩餘搜尋範圍 n=1024 時
開始n1024
第 1 步n/2512
第 2 步n/4256
第 k 步n/2ᵏ1024/2ᵏ
最多 10 步 1 1
當範圍縮到 1 時停止：n/2ᵏ = 1 → 2ᵏ = n → k = log₂n

n=1,000,000,000（10億）時，Binary Search 最多只需 30 步。
📊 對比 線性搜尋：最壞 n 步。n=10 億 → 10 億步。
Binary Search：最壞 log₂n 步。n=10 億 → 30 步。
差距是 10 億 / 30 ≈ 3300 萬倍。
Step 5 · 變形題：找左邊界、找右邊界
陣列中可能有重複元素，題目可能要求找第一個或最後一個出現的位置。
Python 
# 找左邊界：第一個 >= target 的位置（lower_bound）
def lower_bound(arr, target):
    lo, hi = 0, len(arr)   # hi = n（左閉右開 [lo, hi)）
    while lo < hi:           # 注意：不含等號
        mid = (lo + hi) // 2
        if arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid            # 不是 mid-1，因為 mid 可能就是答案
    return lo               # lo 就是第一個 >= target 的位置

# 找右邊界：最後一個 <= target 的位置（upper_bound - 1）
def upper_bound(arr, target):
    lo, hi = 0, len(arr)
    while lo < hi:
        mid = (lo + hi) // 2
        if arr[mid] <= target:
            lo = mid + 1
        else:
            hi = mid
    return lo - 1           # 最後一個 <= target 的 index
「Answer is Binary Search」
更強的應用：當答案具有單調性（答案越大，條件越容易/越難滿足），就能對答案本身做 Binary Search。

例：「找最小的速度，使得 k 小時內能讀完所有書」
→ 速度越大越容易完成 → 對速度做 Binary Search → O(n log(max_speed))
🔑 判斷能否 Binary Search 能對答案做 Binary Search 的條件：存在一個臨界值，使得「小於臨界值的答案都不行，大於等於臨界值的都行」（或反過來）。這種單調性就是 Binary Search 的切入點。
