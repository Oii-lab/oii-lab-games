哪些遊戲用到 DP？
Bachet's Game 和 21點報數 的核心都是同一個 DP 問題，只是換了一層外殼。 DP 的目的是找出每個「狀態」是必贏（W）還是必輸（L）。
狀態定義與轉移
定義 dp[n] = 當剩餘數字（或石頭數）為 n 時，當前輪到的玩家是 W 還是 L。
Python 
# Bachet's Game / 21點報數 通用 DP 解
def solve_dp(n: int, max_take: int) -> list:
    # dp[i] = True 表示當前玩家「必贏」
    dp = [False] * (n + 1)
    dp[0] = False  # 0個石頭 → 上個人已輸
    dp[1] = False  # Misère: 只剩1顆必須取 → 必輸
    for i in range(2, n + 1):
        dp[i] = any(
            not dp[i - take]
            for take in range(1, min(max_take, i) + 1)
            if i - take >= 1
        )
    return dp
# 觀察 dp 陣列：(n=21, max_take=3)
# dp: L  W  W  W  L  W  W  W  L  ...  ← 每 (max_take+1) 循環一次！
💡 關鍵觀察：從 DP 到 O(1)

跑完 DP 後會發現週期性規律：每隔 K = maxTake + 1 格，必輸位置就重複出現一次。

n % (maxTake + 1) == 1 → 當前玩家必輸

這個「DP 推導規律 → 數學公式」的過程在演算法競賽裡非常常見。

最優走法公式
Python 
def best_move(stones: int, max_take: int) -> int:
    if stones == 1: return 1  # 強制輸，沒得選
    k = max_take + 1
    remainder = stones % k
    if remainder == 1: return 1  # 敗局，隨便取
    take = (remainder - 1) if remainder > 0 else k - 1
    return max(1, min(take, max_take, stones - 1))
Bitwise XOR Sprague-Grundy Theorem Nim-value
從單堆到多堆：為什麼需要 XOR？
Bachet's Game 是單堆 Nim，策略是 n % (M+1)。 當有多堆石頭，每次只能從某一堆取時，需要用到位元互斥或（XOR / Nim-sum）。
Nim-sum（XOR）策略
📐 Bouton 定理（1901年）

設各堆石頭數為 a₁, a₂, ..., aₖ，定義 Nim-sum = a₁ XOR a₂ XOR ... XOR aₖ。

Nim-sum = 0 → 當前玩家必輸（L position）
Nim-sum ≠ 0 → 當前玩家必贏（W position）

必勝走法：找到一堆，取走若干顆，使取完後所有堆的 XOR 變為 0。

Python 
def nim_is_losing(heaps) -> bool:
    nim_sum = 0
    for h in heaps:
        nim_sum ^= h
    return nim_sum == 0

def nim_best_move(heaps):
    nim_sum = 0
    for h in heaps: nim_sum ^= h
    if nim_sum == 0:
        for i, h in enumerate(heaps):
            if h > 0: return (i, 1)
    for i, h in enumerate(heaps):
        target = h ^ nim_sum
        if target < h: return (i, h - target)
Sprague-Grundy 定理
Sprague-Grundy 定理說的是：任何一個「公平賽局（impartial game）」都等價於某個大小的 Nim 單堆。 這個「等價大小」叫做 Grundy value（或 nimber），記作 G(s)。
Python 
from functools import lru_cache

def grundy(n, max_take):
    @lru_cache(maxsize=None)
    def g(state):
        if state == 0: return 0
        reachable = {g(state - t) for t in range(1, min(max_take, state) + 1)}
        mex = 0
        while mex in reachable: mex += 1
        return mex
    return g(n)
# Grundy value = 0 ↔ 必輸位置
# 多個獨立子遊戲：G(整體) = G(子遊戲1) XOR G(子遊戲2) XOR ...
Golden Ratio Beatty's Theorem O(1) Formula
必敗位置（Cold positions）
φ Wythoff 定理（1907年）

所有必敗位置 (a, b)（a ≤ b）：

aₙ = ⌊n·φ⌋，bₙ = ⌊n·φ²⌋ = aₙ + n

其中 φ = (1+√5)/2 ≈ 1.618，n = 0, 1, 2, 3, ...
前幾個必敗位置：(0,0), (1,2), (3,5), (4,7), (6,10), (8,13), ...

Python 
import math
PHI = (1 + math.sqrt(5)) / 2

def wythoff_is_losing(a, b) -> bool:
    if a > b: a, b = b, a
    n = b - a
    return int(n * PHI) == a  # O(1) 判斷

def wythoff_best_move(a, b):
    if wythoff_is_losing(a, b): return None
    for na in range(a + 1):
        if wythoff_is_losing(na, b): return (na, b)
    for nb in range(b + 1):
        if wythoff_is_losing(a, nb): return (a, nb)
    for d in range(1, min(a, b) + 1):
        if wythoff_is_losing(a - d, b - d): return (a - d, b - d)
黃金比例為什麼出現在這裡？
關鍵是 Beatty 定理：對於無理數 r 和 s， 若 1/r + 1/s = 1，則 {⌊n·r⌋} 和 {⌊n·s⌋} 恰好把所有正整數不重複地分成兩組。 由於 1/φ + 1/φ² = 1，序列 ⌊n·φ⌋ 和 ⌊n·φ²⌋ 就剛好把所有非負整數配成對，完美對應了 Wythoff 的必敗位置。
Minimax Memoization Alpha-Beta Pruning
Minimax 遞迴定義
Python 
from functools import lru_cache

@lru_cache(maxsize=None)
def is_losing(board: frozenset) -> bool:
    """當前玩家是否在必輸位置（Chomp）"""
    non_poison = {(r,c) for r,c in board if (r,c) != (0,0)}
    if not non_poison: return True
    for (r, c) in non_poison:
        eaten = frozenset(
            (rr, cc) for rr, cc in board
            if not (rr >= r and cc >= c)
        )
        if is_losing(eaten): return False
    return True
Alpha-Beta Pruning（Connect Four 使用）
在大棋盤上，狀態空間仍然太大。Alpha-Beta Pruning 是 Minimax 的優化版本， 透過剪掉「不可能被選到的分支」，在不影響正確性的情況下大幅加速。 最好情況可將搜尋從 O(bd) 降至 O(bd/2)。
Python 
def minimax(state, depth, alpha, beta, is_maximizing):
    if is_terminal(state) or depth == 0:
        return evaluate(state)
    if is_maximizing:
        value = -float('inf')
        for move in get_moves(state):
            value = max(value, minimax(apply(state, move), depth-1, alpha, beta, False))
            alpha = max(alpha, value)
            if beta <= alpha: break  # β 剪枝
        return value
    else:
        value = float('inf')
        for move in get_moves(state):
            value = min(value, minimax(apply(state, move), depth-1, alpha, beta, True))
            beta = min(beta, value)
            if beta <= alpha: break  # α 剪枝
        return value
🔬 記憶化的關鍵

不同走法序列可能產生相同的棋盤狀態。 用 dict 或 @lru_cache 把已算過的狀態存起來， 可以讓時間從 O(moves!) 降到 O(唯一狀態數 × 合法移動數)。

🤯 Chomp 的特殊地位

Chomp 在數學上已被證明先手必勝（Zermelo 定理）， 但目前沒有人知道具體策略是什麼（除少數特殊棋盤大小）。 這是組合賽局理論中的著名開放問題之一。
